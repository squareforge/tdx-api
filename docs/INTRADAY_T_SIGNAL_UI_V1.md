# 日内做T信号 UI 方案 V1（讨论稿）

> 本文档是 `INTRADAY_T_SIGNAL_V1.md` 的配套 UI 设计讨论稿，不等同于代码实现。
> 定位：为人工执行的日内做T信号系统提供一个「执行驾驶舱」——选标的、看信号、看图、标记收尾，全部在一页内闭环。

---

## 1. 设计原则

- **执行驾驶舱，不是监控大屏**：UI 的第一优先级是让用户（手机端也一样）一眼回答三个问题——现在干什么、什么价、什么时候过期；其次是「点一下记账」，让每笔 T 盈亏可复盘。
- **信号卡即文档 JSON 的渲染**：信号字段与 `INTRADAY_T_SIGNAL_V1.md` 4.5 的 JSON 一一对应，天然无失真。
- **图上看到的和信号引擎算的是同一份数据**：分时图数据源必须与信号引擎一致（MinuteBarBuilder 合成的分钟bar），不使用 TDX 服务端分时接口，避免信号标记对不上。

## 2. 页面位置与布局

### 2.1 页面位置（已确认）

- 不做顶级 tab，挂在现有「交易系统」工作区内，拆两个子 tab：
  - **持仓与交易**：现有 `TradingSystemWorkspace`（`apps/web/frontend/src/components/TradingSystemWorkspace.tsx`），内容不变。
  - **日内交易**：新增 `IntradayTradingWorkspace`，承载本文档全部 UI（订阅 / 信号 / 分时图 / 账本）。
- 实现复用「选股」工作区子 tab 模式（`App.tsx` 中 `selectionWorkspaces` + `selection-subtabs`）：新增 `tradingWorkspaces` 数组与 `activeTradingWorkspace` 状态，`destroyOnHidden={false}` 保持切换不丢状态，localStorage 记忆当前子 tab。
- 两个子 tab 数据相互独立：日内交易的手动底仓录入不与「持仓与交易」的持仓记录打通（V1 不引入耦合）。
- 顶部 `terminal-bar` workspace code 按子 tab 展示：`HOLDINGS_TRADING`（持仓与交易）/ `INTRADAY_T`（日内交易）。

### 2.2 桌面端：三栏结构

```text
┌──────────────────────────────────────────────────────────────┐
│ [搜索/选择标的] sz000001 [订阅中] [底仓xxx股] [模式/否决/健康] │  ← 顶部栏
├────────────────────────────────┬─────────────────────────────┤
│                                │  实时信号卡流               │
│        分时图（大，中栏）        │  SELL_FIRST 11.32          │
│   ── VWAP ── 均线 ──           │  目标11.12 / 止损11.42     │
│   ↑卖点标记   ↓买点标记         │  [已成交] [放弃]            │
│   目标/止损虚线                 │  ─────────                │
│   （点击信号点→右栏弹详情）      │  当日账本（卖→买配对）      │
└────────────────────────────────┴─────────────────────────────┘
```

### 2.3 移动端：纵向流（Webhook 点击进来为主场景）

顶部标的/状态条 → 分时图 → 信号卡 → 账本，按此顺序纵向排列；信号卡为手机主操作区，按钮做大，颜色语义化（卖=红、买=绿）。

## 3. 模块细化

### 3.1 搜索订阅（顶部栏）

- 复用现有 `/api/search` 搜索标的；订阅即「绑定做T标的」——V1 单只固定，订阅后整页只服务这一只。
- 订阅持久化到**服务端配置**（非前端 localStorage），页面重开、Webhook 点击进入时标的一致。
- **当日锁定规则（已确认）**：订阅后当天锁定该标的；换标的需手动确认，且清空当日信号与账本，避免中途切标的导致账本混乱。
- 顶部常驻显示：当前标的、订阅状态、底仓规模（**手动录入**，已确认，不与「交易系统」工作区打通）。

### 3.2 信号发出区（右栏）

- 信号卡渲染字段：方向、规则、触发描述、建议价位、目标价、止损价、过期时间、仓位建议（底仓1/3）、回补条件（follow_up）。
- 操作按钮仅两个：`已成交`（点击后进入当日账本记账）、`放弃`（对应 CANCELLED）。
- 当日账本：自动配对「卖出 → 买回」，计算每笔净盈亏（含佣金+印花税+滑点）；未回补的在收盘前提示「放弃回补/隔日处理」。
- 冷却状态显示：单日亏损达底仓 1% 或连亏 3 笔 → 显示「已暂停出信号」及原因。

### 3.3 分时图 + 买卖标记（中栏，核心视图）

- 数据源：MinuteBarBuilder 合成的分钟bar（快照 → 1分钟bar），轮询刷新。
- 叠加线：VWAP、分时均线；可选五档盘口确认信息。
- **信号点标记**：卖点=红向下箭头+价格，买点=绿向上箭头+价格，对应 `SELL_FIRST` / `BUY_BACK`；`REDUCE` / `STAND_ASIDE` 用灰色/空心标记区分。
- **价位线**：目标价/止损价画虚线水平线，范围从信号触发时间到过期时间——一眼看出信号是否仍有效。
- **执行标记**：已标记 `已成交` 的信号，在对应时间点盖上成交标记（颜色加深/实心），与未执行信号区分。

### 3.4 信号-图表互动（新增，已确认）

- 点击分时图上的任意历史信号点 → 右侧弹出该信号完整详情卡片，并带 `补标记成交` / `放弃` 按钮。
- 用途：复盘时点图即操作，操作与查看合一；漏标记的信号可事后补记，账本才完整。

## 4. 数据与接口

### 4.1 后端归属

- 新建 `services/t-signal`（或复用 `services/selection-worker`，其已有 `quote_monitor.go` + `webhooks.go`），独立承载：分钟bar合成（MinuteBarBuilder）、信号引擎、信号持久化、当日账本。
- `apps/web` 只做网关转发，沿用现有 `/api/*` 模式；前端不直连内部服务。

### 4.2 聚合接口（UI 消费）

| 接口 | 作用 | 说明 |
| --- | --- | --- |
| `GET /api/t-signal/state` | 当前标的、模式、趋势否决状态、数据流健康度 | 顶部状态条 |
| `GET /api/t-signal/snapshot` | 分钟bar + 当前信号 + 当日记录 聚合 | 1–3s 轮询主数据源 |
| `GET /api/t-signal/records` | 当日账本（成对交易、净盈亏、冷却状态） | 可与 snapshot 合并 |
| `GET/PUT /api/t-signal/config` | 标的订阅、底仓、S1–S5 参数、费率、开关 | 配置面板 |
| `POST /api/t-signal/:id/ack` | 人工标记 `EXECUTED` / `CANCELLED` | 信号生命周期推进 |

### 4.3 实时性

- 信号为分钟级，UI 轮询 1–3s 拉 snapshot 即可，**不引入 WebSocket**。
- Webhook 只负责「有新信号」的动作提醒；打开页面后通过 snapshot 对齐状态。

### 4.4 持久化要求

- 信号触发后**服务端持久化**（含时间戳），刷新不丢；否则图上标记消失且无法复盘。
- 标记 `已成交` / `放弃` 的操作同样落库，账本以库内状态为准。

## 6. 落地路径

```text
阶段1  后端信号服务   MinuteBarBuilder + 信号引擎 + 持久化（对齐 INTRADAY_T_SIGNAL_V1.md 阶段2/3）
阶段2  聚合接口       /api/t-signal/state、snapshot、records、config、:id/ack
阶段3  前端页面       顶部订阅栏 + 分时图标记 + 信号卡 + 账本（接入 apps/web/frontend 交易系统子 tab「日内交易」）

```

## 7. 风险与备注

- 分时图基于快照合成分钟bar，high/low 存在低估，秒级触发价不可依赖（沿用信号文档 2.4）。
- 图表绘制复用现有前端图表适配层（`chartlib/umychart.min.js` + `chart-adapter.js`），避免引入新的图表库。
- 本文档仅供学习研究与个人复盘使用，不构成投资建议。
