# 历史回测对照组分析需求方案

> 版本：V1.0
> 日期：2026-09-30
> 适用范围：历史选股回放、策略信号分析和回测结果比较
> 性质：需求与实施计划；本文不代表功能已经实现。

## 1. 背景

当前历史回测可以保存策略信号、D1/D3/D5/D10 跟踪结果和组合模拟结果，但单独查看策略收益还不能回答一个核心问题：

> 策略选出的股票，是否真的比同一天市场中其他可选股票更好？

例如，低位三连阳首板在 2026 年前 8 个月的组合收益为正，但信号数量较少；在 2021—2025 年，D10 平均收益接近 0。仅看策略自身的收益，无法区分以下几种情况：

- 策略有选股能力，只是退出规则不合适；
- 策略只是跟随了市场上涨；
- 策略选出的股票和随机股票表现差不多；
- 策略在某种市场风格下有效，换行情阶段就失效。

因此需要在历史回测模块中增加对照分析。对照分析只用于验证和研究策略，不参与实时选股、自动下单或交易风控。

## 2. 目标

### 2.1 主要目标

对每次历史回测生成一份可复现的对照分析报告，至少回答：

1. 策略信号在 D1/D3/D5/D10 的收益是否高于市场基准。
2. 策略信号是否高于同日、同股票池中未入选股票的表现。
3. 策略的收盘达标率、平均收益和中位收益是否高于对照组。
4. 策略的 MFE（期间最高收益）和 MAE（期间最大不利波动）是否优于对照组。
5. 结果是否跨年份、跨市场环境保持一致。
6. 当前结论的样本数量、缺失数据和统计不确定性是什么。

### 2.2 非目标

本需求第一阶段不包括：

- 不改变策略公式、参数或正式选股范围。
- 不把对照组股票加入策略信号或交易组合。
- 不自动执行真实交易，也不向券商发送委托。
- 不用一次随机抽样证明策略永久有效。
- 不使用信号之后才知道的行业、市值或价格信息进行匹配。
- 不把指数基准收益直接当作股票对照组。

## 3. 对照体系

对照分析由两类不同用途的对照组成。页面必须分开显示，不能合并成一个“基准收益”。

### 3.1 指数基准组

固定支持以下四个指数：

| 基准 | 代码 | 用途 |
| --- | --- | --- |
| 上证指数 | `sh000001` | 观察沪市大盘环境 |
| 沪深 300 | `sh000300` | 观察大盘蓝筹表现 |
| 中证 500 | `sh000905` | 观察中盘股表现 |
| 中证 1000 | `sh000852` | 观察中小盘股表现 |

指数基准用于计算市场环境和超额收益。例如：

```text
策略 D5 收盘收益 = 3.00%
中证 500 D5 收益 = 1.20%
策略相对中证 500 超额收益 = 1.80%
```

指数基准不能证明选股能力，因为指数和策略股票的风险暴露不同。它只回答“策略是否跑赢主要市场基准”。

### 3.2 同日匹配股票对照组

同日匹配股票对照组是判断选股能力的主要对照。

对于策略在交易日 `T` 选出的每一条信号，从同一个回测股票池中选择在 `T` 当时可用、可交易、但没有被目标策略选中的股票，形成对照样本。对照股票不参与策略组合，只用于计算后续表现。

示例：

```text
2026-03-18
策略选中：600519、000001
同日候选股票池：1702 只
排除策略选中股票和不可交易股票
随机抽取 5 只作为 600519 的对照组
随机抽取 5 只作为 000001 的对照组
```

同日匹配组的比较单位是“信号事件”，而不是简单把全部股票合并后比较。这样可以避免信号集中在某一天时被其他日期的样本稀释。

## 4. 适用范围与回测口径

### 4.1 只在历史回测模块执行

对照分析挂在历史回测结果上，由用户在结果页主动发起。实时选股、每日复盘和自动化选股不执行同日匹配。

原因：

- 回测的任务是验证策略；
- 实时选股的任务是执行策略；
- 对照组不会产生交易信号，不应增加实时流程的延迟和复杂度。

### 4.2 复用原回测股票池

对照组必须使用原回测的股票池和候选范围，不能另起一个当前全市场列表。这样策略和对照组才处于同一个可比集合中。

第一阶段沿用回测已有的股票池解析方式，并保存以下信息：

- 回测使用的 `universe_pool_ids`；
- 股票池解析时的股票数量；
- 股票池快照版本或摘要；
- 是否使用当前股票列表；
- 退市股票是否可能缺失。

如果原回测只有当前股票列表，报告必须显示幸存者偏差提示。对照组不能假装解决这个问题。

### 4.3 信号时点

对照样本的筛选只能使用信号发生时或信号日收盘前能够获得的信息。禁止使用：

- D1/D3/D5/D10 之后的收益；
- 信号之后才公布的行业或财务数据；
- 事后更新的当前市值替代历史市值；
- 回测结束之后才知道的退市状态。

如果当前系统无法提供历史行业或历史市值，第一阶段不做行业和市值匹配，只做同日、同股票池、可交易过滤，并明确标记为“简单同日随机对照”。

## 5. 同日匹配规则

### 5.1 抽样单位

抽样单位为：

```text
run_id + strategy_id + signal_date + signal_symbol
```

同一天同一只股票被同一个策略重复写入时，只保留一个信号事件。多策略同时命中同一只股票时：

- 如果按单策略分析，每个策略分别建立自己的事件；
- 如果选择“全部策略合并”，该股票只生成一个合并事件，并保留命中的策略列表；
- 页面必须显示分析模式，避免把两种统计混在一起。

### 5.2 对照候选集合

默认候选集合按以下顺序过滤：

1. 股票属于原回测的 `universe_pool_ids`。
2. 股票在信号日之前已经存在于回测可用股票列表。
3. 股票在信号日有可用日线数据。
4. 股票没有停牌、价格缺失或明显无效的 OHLC 数据。
5. 股票不是目标策略在当天选中的信号股票。
6. 股票满足回测股票池已有的基础排除规则。

默认不排除其他策略选中的股票，因为本需求评估的是目标策略相对同日市场的选股能力。页面可以提供“排除全部策略信号”选项，用于生成更严格的清洁对照组，但必须保存该选项。

### 5.3 对照数量

每条信号默认抽取 5 只对照股票，支持以下配置：

- 1 只：快速检查；
- 5 只：默认研究配置；
- 10 只：减少随机波动；
- 20 只：大样本分析。

候选股票不足时全部纳入，并记录实际数量。不能用重复股票补齐数量，除非明确标记为“有放回抽样”。第一阶段采用无放回抽样。

### 5.4 随机种子与可复现

抽样必须固定随机种子，种子由以下内容生成：

```text
run_id
strategy_id
signal_date
signal_symbol
sample_size
matching_algorithm_version
user_seed（可选）
```

相同配置重复查看或重新计算，必须得到完全相同的对照股票清单。用户点击“重新抽样”时，才创建新的 `comparison_id` 和新种子，旧报告必须保留。

### 5.5 分层抽样

第一阶段只要求同日和同股票池。为了减少随机样本偏差，建议按以下可用字段分层：

- 股票板块：沪市主板、深市主板、创业板、科创板、北交所；
- 价格区间：低于 10 元、10—30 元、30 元以上；
- 信号日前的流动性区间：成交额低、中、高。

这些字段必须来自信号时点之前的数据。字段缺失时回退到简单随机抽样，并在报告中记录。

以下匹配暂不作为第一阶段必需条件：

- 历史行业匹配；
- 历史市值匹配；
- 历史贝塔匹配；
- 历史因子暴露匹配。

原因是当前项目尚未保证这些字段具有历史时点一致性。未来补齐历史 `block`、行业和市值快照后，再增加风格匹配对照组。

## 6. 收益和指标口径

### 6.1 价格基准

对照组和策略信号必须使用完全相同的收益口径：

- 信号日收盘价作为信号分析基准；
- D1/D3/D5/D10 使用信号之后的交易日；
- 价格复权方式必须一致；
- 策略和对照组都不能把缺失的交易日填成 0；
- 停牌股票必须记录为不可用或延迟完成。

已有回测是信号日收盘基准，因此第一阶段沿用该口径。未来若增加模拟成交价对照，必须新增独立字段，不能覆盖现有收益。

### 6.2 每个周期必须计算的指标

对于策略和每一个对照组，分别计算：

| 指标 | 定义 |
| --- | --- |
| 平均收盘收益 | 所有有效样本的收盘收益平均值 |
| 中位收盘收益 | 所有有效样本的收盘收益中位数 |
| 收盘达标率 | 收盘收益达到配置阈值的样本比例 |
| 平均开盘收益 | 周期末开盘价相对基准价的平均收益 |
| 平均最高收益 MFE | 周期内最高价相对基准价的平均收益 |
| 平均最低收益 MAE | 周期内最低价相对基准价的平均不利收益 |
| 正收益率 | 周期末收盘收益大于 0 的样本比例 |
| 有效样本数 | 具备完整周期数据的样本数量 |
| 缺失样本数 | 没有完整数据或无法判断的样本数量 |

`MFE` 和 `MAE` 必须与已有跟踪计算保持一致。`MAE` 表示相对基准价的最大不利波动，不应与从历史高点到低点计算的路径最大回撤混用。

### 6.3 成功率阈值

成功率阈值必须作为分析配置保存，不能写死在页面。建议：

- 默认收盘达标阈值：`+1%`，用于检验选股能力；
- 可选阈值：`+3%`、`+5%`、`+10%`；
- 可选附加条件：最大不利波动不低于 `-5%`；
- 页面同时显示阈值，不能只显示“成功率”。

这套分析阈值与组合模拟中的止盈参数分开。组合模拟使用 10% 止盈时，不应自动把对照分析的成功标准改成 10%。

### 6.4 超额收益

对每一个信号事件和周期计算：

```text
相对指数超额收益 = 策略收益 - 指数同期收益
相对对照组超额收益 = 策略收益 - 该事件对照组平均收益
```

对照组应同时保存平均值和中位数，报告默认使用对照组平均收益计算差值，同时允许切换中位数口径。

### 6.5 配对差值

为了避免不同日期行情差异造成误判，必须按信号事件计算配对差值：

```text
事件超额收益 = 信号股票收益 - 同事件对照股票平均收益
```

最终汇总至少显示：

- 配对差值平均值；
- 配对差值中位数；
- 配对差值为正的比例；
- 95% bootstrap 置信区间；
- 有效事件数。

样本数量很少时，页面必须显示“统计区间不稳定”，不能只展示一个百分比。

## 7. 指数收益计算

### 7.1 指数基准数据

指数日线应由后端通过现有行情服务加载，记录：

- 指数代码和名称；
- 数据来源；
- 复权方式；
- 数据版本或更新时间；
- 目标交易日是否存在。

指数收益不参与股票对照抽样。它作为独立基准存储，便于多个策略和多个回测复用。

### 7.2 指数缺失

指数在目标日期没有数据时：

- 不使用相邻自然日代替；
- 不使用 0 收益代替；
- 当前周期标记为 `unavailable`；
- 在报告中单独统计缺失原因。

## 8. 数据模型建议

对照分析使用独立表，不修改历史回测信号和跟踪记录。

### 8.1 对照分析批次表

建议表名：`historical_backtest_comparisons`

核心字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 对照分析 ID |
| `run_id` | 历史回测 ID |
| `strategy_id` | 目标策略；合并分析时可为空 |
| `mode` | `strategy`、`all_strategies` |
| `status` | `queued`、`running`、`completed`、`failed`、`cancelled` |
| `verdict` | `complete`、`partial`、`unavailable` |
| `sample_size` | 每条信号的对照数量 |
| `target_return` | 收盘达标阈值 |
| `drawdown_limit` | 可选回撤阈值 |
| `matching_config_json` | 股票池、过滤和分层配置 |
| `benchmark_ids_json` | 四个指数基准 |
| `seed` | 抽样种子 |
| `algorithm_version` | 匹配算法版本 |
| `event_count` | 信号事件数量 |
| `control_count` | 实际对照样本数量 |
| `started_at`、`finished_at` | 执行时间 |
| `error` | 批次级错误 |

### 8.2 信号事件表

建议表名：`historical_backtest_comparison_events`

核心字段：

| 字段 | 说明 |
| --- | --- |
| `comparison_id` | 对照分析 ID |
| `signal_id` | 原历史回测信号 ID |
| `strategy_id` | 策略 ID |
| `signal_date` | 信号日期 |
| `signal_symbol` | 信号股票 |
| `signal_price` | 回测保存的基准价格 |
| `candidate_count` | 当日候选集合数量 |
| `actual_control_count` | 实际抽取数量 |
| `stratum_json` | 抽样分层 |
| `sampling_seed` | 事件级种子 |
| `status` | `complete`、`partial`、`unavailable` |
| `reason` | 不可用原因 |

### 8.3 对照股票样本表

建议表名：`historical_backtest_comparison_controls`

核心字段：

| 字段 | 说明 |
| --- | --- |
| `event_id` | 信号事件 ID |
| `control_symbol` | 对照股票 |
| `sample_rank` | 抽样顺序 |
| `match_method` | `same_day_random` 或未来扩展值 |
| `pool_id` | 股票池 |
| `board` | 板块 |
| `price_bucket` | 价格分层 |
| `liquidity_bucket` | 流动性分层 |
| `feature_snapshot_json` | 信号时点可见的匹配字段 |
| `status` | 样本状态 |

### 8.4 周期观察表

建议表名：`historical_backtest_comparison_observations`

一条记录对应一只样本股票和一个周期，至少包括：

- `event_id`、`control_id`；
- `side`：`signal`、`control`、`benchmark`；
- `benchmark_id`；
- `horizon_days`；
- 最终交易日和 OHLC；
- 平均收盘价；
- `open_return`、`close_return`、`high_return`、`low_return`；
- `mfe`、`mae`、路径最大回撤；
- `target_hit`、`success`；
- `data_quality`、`source`、`adjustment_type`；
- `reason`。

### 8.5 汇总表或结果 JSON

页面查询使用分页明细，顶部汇总可以保存在 `historical_backtest_comparisons.summary_json`，但明细必须可独立重算。结果 JSON 至少包含：

- 策略组汇总；
- 四个指数汇总；
- 同日对照组汇总；
- 配对差值；
- 分年份汇总；
- 缺失和不可判定统计；
- 计算版本。

## 9. HTTP API 建议

接口继续挂在历史回测资源下，由 Web 后端代理到 `selection-worker`。浏览器不能直接访问行情服务。

### 9.1 创建分析

```http
POST /api/historical-backtests/{run_id}/comparisons
```

请求示例：

```json
{
  "strategy_id": "template-low-three-bull-first-board",
  "mode": "strategy",
  "control_sample_size": 5,
  "target_return": 1,
  "drawdown_limit": 0,
  "benchmark_ids": ["sh000001", "sh000300", "sh000905", "sh000852"],
  "matching_method": "same_day_random",
  "stratify": ["board", "price_bucket"],
  "seed": 20260930,
  "resample": false
}
```

返回对照分析批次和状态，不同步等待全部计算完成。

### 9.2 查询批次

```http
GET /api/historical-backtests/{run_id}/comparisons
GET /api/historical-backtests/{run_id}/comparisons/{comparison_id}
```

详情必须返回：

- 执行状态和进度；
- 样本总数和完成数；
- 策略、指数、对照组的汇总；
- 缺失、异常、不可判定数量；
- 采样配置和算法版本。

### 9.3 查询明细

```http
GET /api/historical-backtests/{run_id}/comparisons/{comparison_id}/events
GET /api/historical-backtests/{run_id}/comparisons/{comparison_id}/observations
GET /api/historical-backtests/{run_id}/comparisons/{comparison_id}/export
```

所有明细接口必须分页。导出 CSV 时保留原始价格、收益、差值、样本状态和原因，不只导出页面格式化后的百分比。

### 9.4 取消和重抽样

```http
POST /api/historical-backtests/{run_id}/comparisons/{comparison_id}/cancel
POST /api/historical-backtests/{run_id}/comparisons/{comparison_id}/resample
```

重新查看不能改变样本。只有明确调用 `resample` 才能创建新样本批次。

## 10. 后台执行要求

### 10.1 异步任务

对照分析必须后台执行，页面关闭后仍能继续。任务要支持：

- `queued`、`running`、`completed`、`failed`、`cancelled`；
- 进度更新；
- 有限重试；
- 服务重启后的恢复或中断标记；
- 一个回测同一时间最多一个运行中的相同分析任务。

### 10.2 请求和缓存

- 相同股票在同一对照分析内只加载一次日线；
- 四个指数按指数和区间缓存；
- 控制行情请求并发，默认不超过行情服务可承受上限；
- 设置 HTTP 超时，不能无限等待；
- 行情来源和复权口径必须显式记录；
- 不允许使用行情接口的静默回退结果冒充指定来源。

### 10.3 错误处理

单个对照股票缺少 D10 数据时，不得让整批任务失败。该样本对应周期标记 `unavailable`，任务继续处理其他样本。

以下情况必须区分：

- 股票没有目标交易日：`missing_date`；
- 停牌或没有有效 OHLC：`not_tradable`；
- 行情服务超时：`source_timeout`；
- 复权版本变化：`version_changed`；
- 对照候选不足：`insufficient_controls`；
- 指数缺失：`benchmark_unavailable`。

不可用样本不计入通过率分母，但必须计入总样本和不可用统计。

## 11. 页面展示要求

在 `HistoricalBacktestWorkspace` 的回测详情中增加“对照分析”入口，不新建一级导航。

### 11.1 启动面板

启动面板至少包含：

- 分析策略或全部策略合并；
- 对照股票数量；
- 收盘达标阈值，默认 1%；
- 可选 MAE/回撤阈值；
- 是否按板块和价格分层；
- 指数基准选择，默认四个全部启用；
- 固定种子或自动生成种子；
- 是否重新抽样。

面板必须显示提示：对照组用于回测研究，不会加入实盘选股或交易。

### 11.2 总览

总览至少显示：

- 策略信号数、对照事件数和实际对照股票数；
- 四个指数基准；
- D1/D3/D5/D10 的策略收益、对照收益、指数收益；
- 收盘达标率差值；
- 平均和中位超额收益；
- 配对差值和置信区间；
- 有效、缺失、不可判定样本数；
- 样本量不足和幸存者偏差提示。

推荐用简单表格优先，避免只用图表隐藏样本量。

### 11.3 明细

明细支持按以下条件筛选：

- 信号日期和年份；
- 策略；
- 信号股票；
- 对照股票；
- 周期；
- `match`、`mismatch`、`unavailable`；
- 收益是否高于对照组。

每一行至少显示：

```text
信号日期、策略、信号股票、对照股票、周期、
策略收益、对照收益、配对差值、指数收益、
MFE、MAE、有效状态、数据来源
```

### 11.4 页面布局

对照分析放在现有 `HistoricalBacktestWorkspace` 的回测详情中，建议作为一个独立 Tab：

```text
历史回测详情
├── 结果总览
├── 信号明细
├── 交易记录
└── 对照分析
```

不新增一级导航，不把对照股票混入“信号明细”或“交易记录”。对照分析的页面宽度和现有回测表格保持一致，允许横向滚动，但第一屏必须看见结论摘要。

### 11.5 回测列表中的入口

在每个已完成回测行的操作区增加一个带图标的“对照分析”按钮：

- `success`：可点击；
- `running`：禁用并显示“回测进行中”；
- `failed`：如果已有信号数据，允许点击；没有可用信号时禁用；
- `cancelled`：如果已有部分信号，允许点击；
- 已有运行中的对照任务：显示“分析中”，点击进入详情而不是重复创建任务。

按钮旁显示最近一次分析的简短状态：`未分析`、`分析中`、`已完成`、`部分可用`或`失败`。不要在列表行中展示大量收益数字，避免和原回测结果混淆。

### 11.6 启动配置抽屉

点击入口后打开右侧抽屉或居中窄弹窗，标题为“新建对照分析”，分为四个区域：

#### A. 分析对象

- 策略选择：默认选择当前回测中的唯一策略；多策略回测提供“选择一个策略”和“全部策略合并”两个选项；
- 分析模式说明：单策略按该策略的信号事件统计，合并模式按同日同股票去重；
- 回测区间、股票池和信号数量只读显示，帮助用户确认分析范围。

#### B. 同日股票对照

- 每条信号对照数量：`1 / 5 / 10 / 20`，默认 `5`；
- 抽样方法：第一阶段固定显示“同日同股票池随机抽样”；未来方法可扩展；
- 分层抽样：板块、价格区间、流动性，第一阶段默认关闭或按可用字段启用；
- 是否排除全部策略当天信号：默认关闭；
- 随机种子：默认自动生成，也允许输入整数；
- 显示“同一配置和种子会得到相同样本”的说明。

#### C. 收益指标

- 收盘达标阈值：默认 `1%`；
- 可选快捷值：`1% / 3% / 5% / 10%`；
- 最大不利波动限制：默认不启用，启用后填写例如 `5%`；
- 周期固定显示为 `D1 / D3 / D5 / D10`，与原回测保持一致，不允许在这里改动原回测周期。

#### D. 指数基准

四个指数默认全部勾选：上证指数、沪深 300、中证 500、中证 1000。用户可以取消某个指数，但至少保留一个基准。指数代码和复权口径以小字显示，避免用户只看到简称。

底部操作：

- 主按钮“开始分析”；
- 次按钮“取消”；
- 参数校验失败时在字段下方显示原因；
- 启动前显示预计规模，例如“74 条信号 × 5 只对照 ≈ 370 个股票事件”。

### 11.7 运行中状态

分析启动后切换到“对照分析” Tab，但不阻塞用户查看其他回测 Tab。顶部显示：

- 当前状态：排队中、分析中、已完成、部分可用或失败；
- 进度：已完成事件 / 总事件；
- 对照样本完成数；
- 当前处理日期；
- 已耗时；
- 最近一次错误或不可用原因。

进度区域下方显示四个阶段：

```text
抽取信号事件 → 生成同日对照 → 加载指数和股票行情 → 计算汇总
```

当前阶段使用明确的高亮状态，完成阶段显示勾选。页面刷新后通过详情接口恢复状态，不依赖浏览器内存。

运行中提供“取消分析”按钮。取消只停止对照任务，不取消原历史回测；已经完成的样本保留并标记为部分结果。

### 11.8 结果总览区

分析完成后，页面顶部按以下顺序展示内容。

#### A. 结论提示条

提示条只使用有条件的研究结论，例如：

- “策略在 D3 的平均收益高于同日对照组，但中位收益差异不明显”；
- “策略相对中证 500 跑输 1.2 个百分点”；
- “样本量为 15 个信号事件，结论仅供观察”；
- “部分周期因行情缺失无法验证”。

提示条不能使用没有统计依据的“策略有效”或“策略失效”。提示条下方显示“生成结论”的配置摘要和计算版本。

#### B. 样本覆盖摘要

用四个紧凑统计卡展示：

| 卡片 | 内容 |
| --- | --- |
| 信号事件 | 总事件数、有效事件数 |
| 对照股票 | 计划数量、实际数量 |
| 数据完成度 | 完整观察数、不可用数 |
| 分析版本 | 抽样算法、种子、生成时间 |

卡片必须同时显示分母，不能只显示“成功率 60%”。

#### C. 周期比较表

这是主结果，默认用表格而不是只用图表：

| 周期 | 策略平均 | 对照平均 | 配对差值 | 策略中位数 | 对照中位数 | 达标率差 | MFE 差 | MAE 差 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| D1 |  |  |  |  |  |  |  |  |
| D3 |  |  |  |  |  |  |  |  |
| D5 |  |  |  |  |  |  |  |  |
| D10 |  |  |  |  |  |  |  |  |

表格上方放置口径标签：“收盘达标阈值 +1%，基准为信号日收盘，收益使用前复权日线”。用户修改分析阈值后，标签和数值一起更新。

#### D. 指数对比表

单独显示四个指数，列包括：指数名称、D1/D3/D5/D10 收益、策略超额收益、有效样本数。指数表不与股票对照表合并，以免用户误以为指数是抽取出来的股票。

#### E. 收益分布

第一阶段可以使用简单的区间分布表，按周期显示：

- 负收益比例；
- 0%—1%；
- 1%—3%；
- 3%—5%；
- 5%以上。

如果使用柱状图，必须同时显示每个区间的样本数。图表不是必需的，不能取代平均值、中位数和明细表。

### 11.9 年度和市场环境视图

总览下方提供“按年份”视图，使用 Tab 或下拉选择年份。每年显示：

- 信号数量；
- 策略平均/中位收益；
- 对照平均/中位收益；
- 配对差值；
- 达标率差值；
- MFE 和 MAE；
- 四个指数的同期收益。

对于信号少于 20 条的年份，整行增加“样本不足”标记。年度表允许横向滚动，但年份和信号数固定在左侧。

后续市场环境视图可按上涨、震荡、下跌筛选，第一阶段若没有稳定的环境分类字段则不显示空的图表入口。

### 11.10 对照明细表

明细默认按“配对差值从低到高”排序，把策略明显跑输对照组的事件优先暴露出来。提供以下筛选栏：

- 日期范围；
- 年份；
- 周期；
- 策略股票代码；
- 对照股票代码；
- 结论状态；
- 策略是否跑赢对照组；
- 仅显示不可用数据。

表格固定显示以下列：

```text
信号日期 | 策略 | 信号股票 | 对照股票 | 周期 |
策略收益 | 对照收益 | 配对差值 | 指数收益 |
MFE | MAE | 样本状态 | 数据来源
```

列标题中明确标注“策略”和“对照”，正负收益使用现有市场涨跌色彩；颜色不能作为唯一信息，数值必须带正负号和百分号。

每行点击后打开详情抽屉，不离开当前 Tab。详情抽屉显示：

- 信号事件基本信息和原回测 ID；
- 抽样方法、随机种子和分层字段；
- 信号股票与对照股票的基准价格；
- D0/D1/D3/D5/D10 的终盘 OHLC 和收益；
- 指数同期收益；
- 缺失数据、复权口径和行情来源；
- “重新校验行情”入口（复用行情校验功能，不重新抽样）。

### 11.11 历史分析记录

对照分析 Tab 内提供“分析记录”折叠区或侧栏，列出该回测的所有分析批次：

- 创建时间；
- 策略和模式；
- 对照数量；
- 达标阈值；
- 随机种子；
- 状态；
- 结论摘要；
- 查看、导出、重新抽样操作。

点击“重新抽样”创建新的分析批次，不覆盖当前报告。旧报告仍可查看，且在页面上显示各自的抽样算法版本。

### 11.12 空状态、错误和警告

#### 没有分析

显示简短说明：“尚未生成同日对照。对照分析用于比较策略与同日市场表现，不会影响原回测。”主按钮为“新建对照分析”。

#### 没有信号

显示：“该回测没有可用于匹配的信号，无法生成对照组。”不显示空表。

#### 对照候选不足

显示实际候选数量和原因，例如：“2024-02-08 只有 2 只可用候选，计划 5 只，已全部纳入。”这不是任务失败。

#### 行情不可用

显示“部分行情不可用”，并提供可展开的原因统计。不可用样本不显示为 0 收益。

#### 样本不足

使用黄色提示而不是红色错误：“当前只有 15 个信号事件，比较结果不稳定。建议扩大区间或等待更多样本。”

#### 版本变化

显示“当前行情版本与原回测可能不同，结果仅能用于当前数据比较”，并把该状态从 `match` 和 `mismatch` 中单独分出。

### 11.13 导出和可读性

- 页面提供“导出 CSV”按钮，使用下载图标并配置 Tooltip；
- 导出范围默认为当前分析全量，不受当前分页影响；
- 导出文件名包含回测 ID、策略 ID、分析日期和随机种子；
- CSV 使用原始数值和明确字段名，例如 `strategy_d5_close_return`、`control_d5_close_return`；
- 表格支持横向滚动，不能压缩列到无法阅读；
- 移动端优先显示周期、策略收益、对照收益、差值和状态，其余字段放到详情抽屉；
- 所有“不可用”显示文字，不显示空白或 `0.00%`。

## 12. 统计解释规则

### 12.1 不只看平均值

页面同时显示平均值和中位数。若平均收益为正而中位数为负，必须提示收益主要由少数极端上涨样本贡献。

### 12.2 样本量提示

建议最低提示标准：

- 少于 20 个信号事件：结论仅供观察；
- 20—50 个事件：可以比较，但稳定性有限；
- 50 个以上事件：可以做初步统计判断；
- 100 个以上事件：才适合做较稳定的分组比较。

这些标准不是策略通过门槛，只用于页面解释。

### 12.3 年度和市场环境拆分

报告必须支持按年份查看：

- 信号数；
- 策略平均和中位收益；
- 对照组平均和中位收益；
- 超额收益；
- 达标率差值；
- MFE/MAE。

后续可增加按指数趋势、波动率和上涨/下跌环境分组。不能只用整个 2021—2025 区间的累计收益下结论。

### 12.4 结论文案

页面使用以下表述：

- “策略高于同日对照组”；
- “策略低于主要指数基准”；
- “策略与对照组差异不明显”；
- “样本量不足”；
- “部分样本无法验证”；
- “结果可能受行情版本或幸存者偏差影响”。

不能直接显示“策略有效”“策略失效”作为没有统计条件的结论。

## 13. 验收标准

1. 对任意成功历史回测，可以从结果页发起对照分析，原回测信号、交易记录和跟踪数据不被修改。
2. 默认分析包含上证指数、沪深 300、中证 500、中证 1000 四个基准。
3. 对照股票来自同日、同一回测股票池，并排除目标策略当天选中的股票。
4. 相同回测、策略、样本数量、种子和算法版本重复执行，得到完全相同的对照股票清单。
5. D1/D3/D5/D10 均按后续交易日计算，不能按自然日或数组下标错误替代。
6. 策略、同日对照组和指数基准使用相同的复权和收益口径。
7. 页面同时展示平均收益、中位收益、达标率、MFE、MAE、有效样本数和不可用样本数。
8. 成功率阈值默认是 1%，且可配置并保存；不能自动复用组合模拟的 10% 止盈阈值。
9. 每条信号事件可以查看对应的对照股票和配对收益差值。
10. 行情缺失、停牌、接口超时和版本变化不会被计为策略成功或对照成功。
11. 样本量不足时页面展示明确提示，并提供按年份拆分结果。
12. CSV 导出与页面汇总的事件数、有效数和收益统计一致。
13. 对照分析只在历史回测模块运行，不改变实时选股结果和实盘交易流程。

## 14. 测试要求

### 14.1 抽样测试

- 固定种子得到固定股票清单；
- 改变种子后股票清单变化；
- 候选不足时不重复抽样并记录原因；
- 同一信号股票不会进入自己的对照组；
- 同日多策略信号按选择的分析模式正确去重。

### 14.2 收益计算测试

- D1/D3/D5/D10 跨周末和节假日取正确交易日；
- 价格复权口径一致时收益重算正确；
- 缺少一个周期数据时只影响对应观察，不影响整批任务；
- 平均值、中位数、达标率和配对差值计算正确；
- 指数缺失不会被当成 0 收益。

### 14.3 防未来数据测试

- 控制股票筛选不能读取 D1 之后的行情；
- 行业、市值等未提供历史快照时不能启用匹配；
- 当前股票列表不能被误标为历史完整股票池；
- 对照组不会进入策略交易记录。

### 14.4 API 和页面测试

- 重复点击不会创建重复运行中的任务；
- 页面刷新后能恢复任务状态和历史报告；
- 取消、失败和部分不可用状态能正确展示；
- CSV 导出分页和总计一致。

## 15. 实施阶段

### 阶段一：最小可用版本

1. 新增对照分析批次、事件、样本和观察记录。
2. 支持同日同股票池随机对照，每条信号默认 5 只。
3. 支持四个指数基准。
4. 支持 D1/D3/D5/D10 的平均收益、中位收益、达标率、MFE、MAE。

6. 在历史回测结果页增加启动和结果展示。

1. 增加板块、价格、流动性分层抽样。
2. 增加 bootstrap 置信区间和年度汇总。
3. 增加多次重抽样，展示结果区间。
4. 增加按市场上涨、震荡、下跌环境分组。

### 阶段三：风格匹配

在历史行业、历史市值和历史风格字段可追溯后增加：

- 行业匹配对照组；
- 市值匹配对照组；
- 贝塔和波动率匹配；
- 倾向得分或近邻匹配。

风格匹配必须保留信号时点快照，不能直接使用当前行业字段替代历史行业。

### 阶段四：回测前预检

在行情加载完成、策略逐日扫描开始前，执行轻量对照和数据完整性预检。该阶段属于行情质量和回测可信度增强，不应阻塞阶段一的结果分析功能。

## 16. 最终判断标准

对一个策略，至少同时满足以下条件，才可以称为“值得继续验证”：

1. 多个年份中，策略相对同日对照组的配对超额收益大多为正；
2. D1/D3/D5 中至少有一个周期的中位收益和达标率持续高于对照组；
3. 结果不只由少数极端上涨样本贡献；
4. 相对四个指数基准不是持续跑输；
5. 最大不利波动没有明显劣于对照组；
6. 换随机种子、年份和对照数量后，结论方向基本稳定；
7. 在未参与调参的样本外区间仍然成立。

对照组分析不能单独证明策略一定盈利，但它能把“策略选股能力”“市场行情影响”和“交易退出规则”拆开，是继续优化低位三连阳等策略前必须补齐的验证环节。
