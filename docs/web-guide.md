# Web 使用说明

Web 页面入口：`http://localhost:8080`。

## 基本流程

1. 在搜索框输入股票代码或名称，例如 `000001`、`600519`、`平安银行`。
2. 点击搜索后进入股票详情。
3. 在标签页查看五档行情、K 线图、分时图和分时成交。
4. 在 K 线图上切换日 K、周 K、月 K、30 分、15 分、5 分。

顶部工作区还提供：

- `专业行情`：面向 HQChart 接入预留的数据展示页，当前使用同一套 K 线适配接口绘制专业 K 线。
- `公式`：新增、编辑、删除自定义公式，并可选择股票做公式测试。
- `选股结果`：查看选股任务命中的股票，可按公式、股票代码和最近一次运行筛选，并一键打开专业行情。
- `交易系统`：记录个人交易卡，自动计算仓位、浮动盈亏、计划亏损和账户风险，并支持导入导出本地 JSON。
- `自动化`：维护股票池、创建选股任务、手动运行任务、查看运行记录。
- `Webhook`：维护可选通知地址，任务完成或失败时按事件发送 JSON 通知。
- `预警中心`：同步宏观日历、配置风险窗口、查看持仓/观察池关联提示，并可选择 Webhook 通知。
- `数据中心`：查看 Hikyuu 研究数据版本、覆盖文件和质量检查；同步成功会生成可追溯的数据修订号。
- `AI 选股`：选择选股结果、股票池或手动候选，先执行 Hikyuu MA 参考验证，再由 AI 在候选集内排序；点击研究按钮查看单股证据报告。
- `研究助手`：右下角悬浮按钮打开当前工作区上下文对话，沿用原 AI 问答能力。

## 页面数据

| 区域 | 内容 |
| --- | --- |
| 基本信息 | 最新价、涨跌额、涨跌幅、成交量、成交额、开高低 |
| 五档行情 | 买一到买五、卖一到卖五 |
| K 线图 | 蜡烛图、成交量、多周期切换 |
| 分时图 | 当日或指定日期分时走势 |
| 分时成交 | 最近或指定日期逐笔成交 |
| 专业行情 | `/api/hqchart/kline` 适配后的页面数据，以及 `/api/hqchart/history` 返回的 HQChart 原生 K 线数组 |
| 公式管理 | `formulas` 表，保存名称、类型、脚本、周期、复权参数 |
| 交易系统 | 服务端 `trading_system_state` 表为主，浏览器 `localStorage` 用作离线兜底缓存 |
| 自动化任务 | `automation_tasks` 表，保存 Cron、任务类型、payload、Webhook 关联 |
| AI 分析 | `ai_credentials` 和 `ai_analysis_runs` 表，保存脱敏凭据配置、Prompt 版本、数据修订号、工具清单与分析记录 |

## 交易系统

交易系统入口位于顶部工作区 `交易系统`。当前版本用于个人交易计划、风控计算和复盘记录，并支持定时刷新持仓参考价。

默认内置一笔税友股份样本：

```text
总资产：56279.20
本金：50000.00
股票：税友股份 603171
买入价：40.80
股数：300
技术无效点：39.60
```

页面会自动计算持仓市值、仓位占比、浮动盈亏、最大计划亏损和账户风险。数据优先保存到服务端 SQLite，同时写入浏览器本地缓存兜底；可用 `导出` 备份，也可用 `导入` 恢复。完整规则见 [TRADING_SYSTEM_V1.md](TRADING_SYSTEM_V1.md)。

## 公式和选股

K 线分析中的 `Hikyuu 校验` 会请求统一指标接口，返回实际计算引擎和数据修订号；策略中心的 `Hikyuu 校验` 使用 MA 交叉参考回测，和默认 Go 回测并行展示，适合核对信号和收益差异。

Docker 镜像会从随项目包含的 hqchartPy2 源码编译 `HQChartPy2` 扩展。公式 worker 启动后会优先使用 HQChartPy2 的 C++ 引擎执行公式；如果模块不可用或单次执行失败，会回退到内置 Python 执行器，继续保证本地闭环。

内置 fallback 执行器支持常见函数：`MA`、`EMA`、`SMA`、`REF`、`LLV`、`HHV`、`CROSS`、`SUM`、`STD`、`IF`、`MAX`、`MIN`。

示例公式：

```text
CROSS(MA(C,5),MA(C,20));
```

选股任务需要选择一个公式和一个股票池，可以手动运行，也可以填写六段 Cron 表达式定时运行，例如 `0 30 21 * * *`。

命中的股票会写入选股结果中心，不需要再从运行记录的 JSON 里翻结果。

选股结果中心的“刷新跟踪”会按信号后的第 1、5、10 个交易日评估真实表现，默认以 5 日收盘收益达到 3% 且最大回撤不超过 5% 作为达标标准。目标收益和最大回撤可以在页面调整。页面展示的是历史前向表现，不代表未来收益承诺。

选股任务会按 `batch_size` 分批执行，默认 50 只一批；`continue_on_error=true` 时，单批失败会降级为逐只执行并记录失败股票，不会轻易中断整个任务。

## 系统任务

自动化页面提供系统任务模板：

- 早盘基础同步：同步代码库和交易日。
- 晚盘日 K 同步：同步日 K 数据。
- 晚盘完整同步：同步基础数据、日 K、除权、板块、行业、统计、新股申购，并按 `max_codes` 抓取财务快照。
- 选股结果跟踪：收盘后更新已有命中结果的前向表现，可在自动化页面启用。

模板默认不启用，创建后可以检查 Cron 和 payload，再手动启用。

系统同步支持的常用 `scope`：

```text
basic, codes, workday, kline, gbbq, finance, f10, block, industry, stat, stat2, xgsg, all
```

`finance`、`f10`、`block`、`industry`、`stat`、`stat2`、`xgsg` 会写入 `data/database/snapshots/` 下的 JSON 快照。

自定义任务支持：

```json
{"action":"noop","data":{"note":"仅记录一次运行"}}
```

```json
{"action":"system_sync","sync":{"scope":"block","block_files":["gn"],"with_index":true}}
```

```json
{"action":"http_request","method":"POST","url":"http://127.0.0.1:8080/api/health","body":{}}
```

## Webhook

Webhook 使用 `POST` JSON：

```json
{
  "event": "stock_selection.finished",
  "task_name": "晚间选股",
  "status": "success",
  "matched_count": 3,
  "run_at": "2026-06-06T21:30:00+08:00"
}
```

## 宏观预警

预警中心从 BLS、Federal Reserve 和 BEA 的官方公开日程同步 CPI、非农、FOMC 和 PCE。官方同步失败不会删除上次成功的官方日历；首次同步失败时该来源没有可展示的官方事件。BLS 在部分网络环境可能返回 403，页面会显示来源状态。手动添加的事件会保留，不会被官方同步清理。提醒规则按事件发布时间计算“提前提醒”和事件前后风险窗口，处于窗口时交易系统会同步展示提示，但不会自动禁止交易。

如需外部通知，先在 `Webhook` 工作区创建并启用渠道，再在预警中心的 `提醒规则` 中打开 Webhook，填写渠道 ID JSON 字符串，例如 `["risk-feishu"]`。系统发送 `macro_event.alert_due` 和 `macro_event.window_started`，同一事件、渠道和类型只发送一次。事件的 A 股交易日优先由行情服务交易日历计算，无法确认时会标记为待确认。

## 使用建议

- 日/周/月 K 线默认使用同花顺前复权数据。
- Docker 模式会自动启动公式 worker；源码模式需要先运行 `python3 services/formula-worker/worker.py`。
- 可通过 `/api/formula/health` 查看当前公式引擎，`engine=hqchartpy2` 表示已经使用 HQChartPy2。
- 原始通达信 K 线可调用 `/api/kline-all/tdx`。
- 如果遇到分时为空，先确认查询日期是否为交易日。
- 浏览器控制台报错时，先刷新页面并确认服务仍在运行。
