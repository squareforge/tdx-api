# 历史回测行情抽样校验需求方案

> 版本：V1.0
> 日期：2026-09-29
> 适用范围：历史选股回放及其 D1/D3/D5/D10 跟踪结果
> 性质：需求与实施计划；本文不代表功能已经实现。

## 1. 背景与目标

2026-09-28 和 2026-09-29 对同一区间（2021-01-01 至 2025-12-31）执行的两次历史回测，分别保存了 42,743 和 42,758 条信号。其中 1,458 条共同信号的信号价不同。对其中 9 个不同股票和日期的样本进行 HTTP 核对后，通达信未复权收盘价与 Hikyuu 未复权收盘价一致；当天新回测的信号价与当前 Hikyuu 前复权收盘价一致。该抽样结果不能证明其余差异的原因，也不能证明旧回测运行时使用的数据一定错误。

一次多年回测接近一小时。用户需要在结果页快速回答：这次回测实际使用了什么行情、抽样价格能否被独立核对、D1/D3/D5/D10 的价格和收益是否能重算、哪些问题需要重新导入行情或重跑回测。

本需求分两步实施：

1. **第一阶段（本次优先）**：在每次历史回测的结果区增加“数据校验”按钮，针对该回测执行可重复的抽样审计，保存并展示证据。
2. **第二阶段**：把同一套源数据检查接到回测启动流程，在历史 K 线加载完成、逐日策略扫描开始前预检，尽早发现确定的行情错误。

抽样只能提供抽到的样本的证据，页面不能把“抽样通过”描述成“全量数据正确”。

## 2. 当前实现与约束

- 回测入口在 `HistoricalBacktestWorkspace`，批次和结果通过 `/api/historical-backtests` 及其子路径读取。结果页已有策略排行、信号明细、多策略共振和交易记录。
- `selection-worker` 的 `loadSystemBatchKlines` 请求 `market-service` 的 `/api/hikyuu/kline/batch`，参数为 `day`、`recover=qfq`；历史信号日收盘价保存在 `historical_backtest_signals.latest`，D1/D3/D5/D10 跟踪保存在 `selection_result_tracking`。
- `market-service` 的 `/api/kline-all/tdx` **先尝试 Hikyuu，失败后才请求通达信**。接口名不能证明实际来源，必须核对响应 `data.meta.source`；校验任务需要一个明确的“强制通达信、禁止回退”读取路径。
- `/api/hikyuu/kline/batch` 在 Hikyuu 缺失时会回退到通达信原始日线，即使请求参数是 `recover=qfq`。回测必须按股票记录实际数据来源和复权状态；原始价回退不能被当作前复权价通过校验。
- 当前历史回测构造跟踪计算输入时只设置 `Latest`，没有设置 `SignalPrice` 和 `SnapshotStatus`，因此其跟踪记录的 `data_quality` 可能统一标成 `suspect`。抽样校验必须使用独立状态，不得直接以此字段决定通过或失败。
- 通达信日线是**未复权价**，回测信号价是**前复权价**。二者不能直接相减判定对错。复权基准还会随新增除权除息事件改变；仅查询单日窗口也可能得到与完整历史序列不同的前复权值。

## 3. 范围与非目标

### 3.1 本次需要交付

- 已保存的成功回测可从结果页发起、查看和重新执行数据校验；有部分信号的失败或取消回测也允许手动校验已有数据。
- 校验固定抽样规则、保留样本清单和结果；重复查看同一份报告不能重新随机取样。
- 同时展示通达信未复权、Hikyuu 未复权、回测保存的前复权价格，以及可取得的当前前复权价格。
- 对信号日和 D1/D3/D5/D10 终盘价进行检查；对所需日线齐全的样本重算收益及路径指标。
- 检查返回数据的实际来源、交易日期、缺失值、行情版本和复权口径；无法判断时显示“不可判定”，不能显示“通过”。
- 后端异步执行，保存报告，支持进度、错误和重试，不阻塞回测结果页面。

### 3.2 不包含

- 不自动修正历史行情、回测信号或交易记录；异常需要先确认数据源和复权版本，再决定是否重跑。
- 不用少量抽样推断全量错误率；不因抽样通过承诺策略收益可靠。
- 不把信号日收盘价当作盘中真实可成交价格；本功能校验的是历史回放所用日线数据和派生结果。
- 第一阶段不对参数扫描、实时策略信号和模拟成交执行同一套审计。

## 4. 用户流程

### 4.1 回测结果页

1. 选择一个历史回测批次，结果卡右上角显示“数据校验”按钮和该批次最近一次校验状态；它与“取消回测”并列，不放到单条信号操作中。
2. 点击按钮后展示默认样本量、抽样范围及本次检查项。用户可以直接开始；默认 50 个不同的“股票 + 信号日”样本，允许选择 20、50、100。
3. 启动后页面显示进度：已抽样、已完成、异常、不可判定。离开页面不取消后台任务。
4. 完成后显示摘要、样本表和异常明细。点击样本可看各价格、具体日期、来源、差值、阈值、失败原因和 HTTP 错误。
5. “重新校验”沿用同一批样本，比较当前数据是否变化；“重新抽样”生成新校验批次和新种子，原报告保留。
6. 报告可按股票、策略、年份、结论筛选，并支持 CSV 导出。CSV 保留原始数值、比较阈值和来源，不只导出颜色标签。

### 4.2 回测前预检（第二阶段）

在 K 线批量加载完成后、逐日扫描开始前，基于候选股票和回测区间执行轻量抽样：先确认来源、未复权原始 OHLC 与通达信一致，再检查前复权数据的复权状态。出现**确定的价格不一致或把未复权回退数据冒充前复权数据**时停止本次回测，并在运行详情中展示样本证据。通达信不可用属于“无法校验”，应单独记录，不能伪装为价格一致或价格错误；交互式运行需让用户明确选择重试或带警告继续，自动运行按配置决定是否提前失败。

预检与结果页复核使用同一套来源检查规则，但预检尚无策略信号，只能从候选股票和交易日抽样；结果页复核从实际信号抽样。两份报告必须标明不同阶段。

## 5. 抽样规则

### 5.1 抽样单位与可复现性

- 抽样单位为 `run_id + 标准化股票代码 + signal_date`；同一股票同日被多个策略选中，只请求一次行情，但报告列出涉及的所有策略和信号 ID，并逐条检查其保存值。
- 用回测 ID、抽样算法版本和用户选择的样本量生成固定随机种子。相同参数应得到完全相同、顺序稳定的样本清单；新随机样本需要显式创建另一份报告。
- 实际样本不足目标数量时全部纳入，并显示“可抽样总数 / 实际抽样数”。不能在失败后悄悄换样本。

### 5.2 覆盖分层

优先保证不同年份和不同策略有覆盖；在可用样本中再兼顾价格区间、前复权与未复权差异较大的股票、发生过除权除息的股票、回测区间首尾。若样本量小于策略数，报告需列出未覆盖策略。任一分层候选不足时把配额分配给其他分层，并记录最终覆盖统计。

50 条是兼顾调用耗时的默认值，不是可靠性保证。若异常在总体中占约 3.4%，均匀独立抽 50 条发现至少一条的概率约 82%，抽 100 条约 97%；实际异常往往集中于特定股票或年份，所以需要分层，同时提供 100 条选项。

## 6. 校验口径与判定

### 6.1 数据读取

| 数据 | 用途 | 来源要求 |
| --- | --- | --- |
| 回测记录 | 被校验的信号价、D1/D3/D5/D10 日期和价格 | `historical_backtest_signals`、`selection_result_tracking`；只读 |
| 通达信未复权日线 | 外部原始 OHLC 参考 | `market-service` 经 HTTP 强制访问通达信；不能回退；响应需显式标识 `tdx` |
| Hikyuu 未复权日线 | 对照本地原始行情 | `recover=none`，记录服务和数据版本 |
| Hikyuu 前复权日线 | 对照当前本地复权行情 | `recover=qfq`，从足够完整的历史序列按交易日取值 |
| 通达信除权除息 | 独立复权复核 | `gbbq` 中的除权除息事件，算法口径见 `docs/gbbq-adjustment.md` |

收到 HTTP 响应后先检查请求是否成功、股票代码和市场是否一致、交易日是否存在。价格按 `symbol + YYYY-MM-DD` 精确匹配，不允许取相邻交易日代替；D1/D3/D5/D10 使用回测记录保存的 `final_date`，不按自然日推算。原始 K 线按股票批量读取并在任务内复用，避免同一股票重复请求整段历史。

前复权查询要使用与回测可比的完整序列、相同 `recover` 和锚定日。查询单日 `start=end` 得到的结果不能用来判定历史回测对错。需要保存请求的 `limit`、序列最末交易日和复权锚点；对旧回测拿不到原始锚点时必须标明限制。

### 6.2 必须检查的层次

| 层次 | 比较内容 | 可得出的结论 |
| --- | --- | --- |
| 原始行情 | 通达信未复权 vs Hikyuu 未复权：样本日期、开高低收；检查 `high >= max(open, close)`、`low <= min(open, close)`、正价格、日期递增且不重复 | 能判断本地原始行情是否与独立 HTTP 来源一致 |
| 回测输入 | 回测保存的信号日基准价 vs 该次回测加载的前复权日线快照；核对每只股票的实际来源和复权状态 | 能判断回测是否按声明口径使用行情 |
| 当前行情 | 回测保存的信号价及各周期终盘 OHLC vs 当前 Hikyuu 前复权日线 | 只能说明与**当前版本**是否一致；复权版本变化时不能单独判旧结果错误 |
| 派生指标 | 按样本 D1 至 D10 的前复权日线和已保存的基准价，重算终盘开/收收益、均收收益、MFE、MAE、路径最大回撤及目标/止损触达 | 能判断已保存指标与对应行情路径是否一致 |
| 独立复权（增强） | 通达信未复权日线 + 通达信 `gbbq` 事件，独立构造指定锚点的前复权价，再与本地前复权价比较 | 能进一步区分原始数据错误与复权因子/算法错误 |

信号基准是历史回测的**信号日收盘价**。示例：`D3 收盘收益 = (D3 final_close / signal_day_close - 1) * 100%`。信号与路径价格一律保持同一复权口径；未复权价只与未复权价比较。`gbbq` 独立复权尚未接入时，页面只显示“原始行情一致、当前前复权一致”，不能声称“前复权已独立验证”。

### 6.3 精度、异常与版本变化

- 原始 OHLC 统一到分（0.01 元）后逐字段比较；浮点序列化误差不算价差。前复权值按回测保存精度比较：信号价和终盘价以厘（0.001 元）为基准，收益按当前 `tracking-v3` 的百分比两位小数规则重算。独立复权与 Hikyuu 的舍入规则可能不同，其容差单独版本化，报告必须同时显示未经舍入的差值。
- 一分钱的未复权差异、缺少某一方的目标交易日、字段越界或错误的实际数据来源都记录为具体异常，不用“平均误差”掩盖单条错误。
- 如果当前 K 线或复权因子版本与运行时版本不同，保存值与当前前复权价不同时标记“版本变化，无法据此判旧回测对错”；原始价比较和记录自身的数学一致性仍可分别给出结论。
- 遇到停牌、退市、除权日、跨年 D10、旧数据缺失或 HTTP 超时，显示单独原因；不能用 0 填补价格，也不能把“无数据”计入通过数。
- 同一交易日多个策略命中同一股票，应先校验行情一次，再检查所有相关信号价格是否一致；任何一条不一致都应在报告里定位到信号 ID。

### 6.4 状态定义

任务状态与业务结论分离。任务状态为 `queued / running / completed / error`。单项结论为 `match / mismatch / unavailable / version_changed`，并保存原因码；其中 `unavailable` 表示接口失败、目标日期缺失或旧数据不足以判定，不等于价格错误。

整份报告显示：

- **发现不一致**：至少一项有可确认的错误来源、原始价不一致、同版本前复权价不一致或派生指标计算不一致。
- **抽样一致**：原始行情、运行时快照、独立复权和派生指标检查均完成且一致，并明确写出“仅覆盖 N 个样本”。
- **部分可验证**：已完成的检查一致，但缺少独立复权或运行时快照，或者部分来源不可用、版本已变化。第一阶段尚未接入独立复权时，即使原始价和当前前复权价全部吻合，也应显示此状态及各层的具体结果。
- **无法校验**：没有足够的有效样本或必需来源整体不可用。

不得只用 `selection_result_tracking.data_quality` 生成上述状态；该字段原有语义和历史回测填充路径需要单独梳理。

## 7. 数据留存与接口设计

### 7.1 建议的数据模型

新增独立审计表，避免改写已完成的回测结果：

| 实体 | 核心字段 | 用途 |
| --- | --- | --- |
| 校验批次 | `id`、`run_id`、`phase`、`status`、`verdict`、`seed`、`algorithm_version`、`sample_target`、覆盖及各结论计数、`started_at`、`finished_at`、`error` | 保存每次审计及进度 |
| 样本 | `validation_id`、`symbol`、`signal_date`、关联 `signal_ids`/`strategy_ids`、抽样分层、实际来源、复权锚点、版本信息 | 固定样本集合及来源 |
| 检查明细 | `sample_id`、`check_type`、`price_field`、`trading_date`、`expected`、`actual`、`difference`、`tolerance`、`status`、`reason_code` | 保留可追溯证据 |
| 回测行情清单 | `run_id`、`symbol`、`recover`、`source`、加载时间、请求 `limit`、首末交易日、数据/因子版本或摘要 | 区分运行时数据和事后当前数据 |

对于新回测，在行情仍位于内存时固定样本并保存其 D0 至 D10 所需前复权日线快照或等价可重放数据，以及每只股票加载序列的摘要。这样以后可校验“当时用了什么价格”。只保存摘要可以识别数据变化，但无法重建旧 K 线；不能把摘要当成完整快照。旧回测没有这些资料时，报告标明“仅能与当前数据比较”。

审计明细只存用于核对的价格、日期、来源和错误，不保存整份通达信 HTTP 原文响应。数据读取只读；重新校验新增审计记录，不覆盖旧报告，也不改写历史信号或跟踪结果。

### 7.2 建议的 HTTP 契约

| 方法与路径 | 行为 |
| --- | --- |
| `POST /api/historical-backtests/{id}/validations` | 创建异步校验；参数包含 `sample_size`、`resample`；返回校验批次 ID |
| `GET /api/historical-backtests/{id}/validations` | 列出该回测的历史校验报告及摘要 |
| `GET /api/historical-backtests/{id}/validations/{validation_id}` | 查询进度、覆盖、结论及分页明细 |
| `GET /api/historical-backtests/{id}/validations/{validation_id}/export` | 下载当前报告 CSV |

前端继续通过现有 Web 到 `selection-worker` 的历史回测代理访问。通达信原始日线应由后端通过 `market-service` 的明确强制来源接口请求；**不得让浏览器直接连接 Docker 服务**。新接口需要限制样本量和同时运行的校验任务，并对重复点击返回既有运行中任务，避免重复压满行情服务。

## 8. 页面展示要求

结果卡保持当前信息密度，在批次标题操作区加入按钮与简短状态标记。报告作为结果区内的独立视图或抽屉，不新建一级导航。顶部摘要至少展示：回测 ID、原回测完成时间、本次校验时间、样本数/可抽样数、覆盖的策略和年份、原始行情一致数、前复权一致数、异常数、不可判定数、数据版本变化数。

样本明细至少展示：`股票/名称`、`信号日`、`策略`、`检查日期/周期`、`字段`、`回测保存值`、`通达信未复权值`、`本地未复权值`、`当前前复权值`、`来源`、`差值`、`结论`。表头必须说明价格口径；空值显示“无数据/未校验”，不能显示 `0.000`。默认把异常和不可判定项排在前面；正常样本仍可查看。

页面文案使用“抽样一致”“发现不一致”“版本变化”“来源不可用”，不使用没有证据支撑的“昨天回测错误”或“本次回测完全正确”。旧回测无行情快照时，应在摘要显著说明证据局限。

## 9. 性能与可靠性

- 校验由后台任务执行；HTTP 请求设置超时、有限重试和全局并发上限，默认最多 4 个通达信股票请求并发，具体值需与 `market-service` 可承受能力联调。单只股票的整段日线只取一次并在任务内复用。
- 任务可在 Web 页面关闭后继续；服务重启后不能把仍标记 `running` 的任务永远留在运行中，应恢复或标记中断并可重试。
- 外部接口暂时不可用时保存错误和已完成检查；禁止用 Hikyuu 回退结果伪装成通达信独立验证。
- 对新回测做完整的本地数学一致性检查可独立于 HTTP 抽样运行；网络抽样只检查有限样本。两种覆盖范围应分别显示。
- 导出和查询使用分页，不能一次把数万条信号或整段原始 K 线送到浏览器。

## 10. 验收标准

1. 选择任意成功回测后能发起校验；报告保存在数据库中，刷新页面或重启服务后仍可查看，原回测信号与跟踪记录未被修改。
2. 同一回测、同一种子和抽样算法版本，重复运行得到相同 `symbol + signal_date` 清单；“重新抽样”生成新清单并保留旧报告。
3. 对已知价格一致的样本，通达信真实返回源被识别为 `tdx`，未复权价与 Hikyuu 未复权价一致，当前前复权价与回测保存值在同版本条件下吻合。
4. 把 HTTP 路由模拟成返回 `meta.source=hikyuu` 时，报告显示“通达信来源不可用”，绝不计为独立校验通过。
5. 注入一条未复权收盘价差异、一条错误的信号价、一条 D3 收盘价或收益计算差异，都能定位到股票、日期、字段、保存值和参考值；其余样本继续完成。
6. 注入 Hikyuu/通达信超时、停牌缺日、旧回测缺少行情快照、复权锚点或因子版本变化时，返回明确的不可判定原因，不把该样本计为一致或错误。
7. D1/D3/D5/D10 按跟踪记录的交易日期检查，跨周末和跨回测结束日仍取正确的后续交易日；路径指标的重算使用同一组复权 K 线和当前计算版本。
8. 校验任务同时运行数量受限；前端有进行中、完成、异常和不可判定状态，CSV 与页面汇总计数一致。
9. 第二阶段预检在逐日扫描前完成；确定的数据异常能提前停止运行并留下报告，来源不可用时按明确策略提示或失败，不会静默回退成“通过”。

## 11. 实施顺序

1. 先补强行情来源标识和强制通达信读取能力，并明确 `recover=qfq` 遇到未复权回退时的处理；这是后续校验可信的前提。
2. 实现抽样器、后台任务、审计表和原始价/当前前复权/记录内数学一致性检查；接入回测结果页按钮和报告。
3. 为新回测保存每只股票的行情来源、复权锚点与版本摘要，并留存抽中样本的运行时 K 线快照；旧回测按“历史快照缺失”兼容展示。
4. 接入 `gbbq` 独立复权复核，区分原始价、复权因子和历史版本问题。
5. 把可复用的源数据检查移到回测加载后作为预检，验证异常时的停止、重试和人工继续流程。
