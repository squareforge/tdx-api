# 每日复盘增强版：策略信号分析 Web UI 设计方案

> 版本：V1.0  
> 日期：2026-09-24  
> 适用项目：`/Users/admin/Documents/learn/python/tdx-api`  
> 设计原则：以现有“每日复盘”页面为主入口，通过增量改造承载策略信号分析、模拟跟踪和后续交易状态，不新增一套平行的策略分析工作台。

## 1. 设计结论

最终用户应该在现有每日复盘页面里完成下面这条工作流：

```text
查看当天策略批次
    -> 查看股票和策略信号
    -> 查看信号价与行情时间
    -> 查看 D0/D1/D3/D5/D10 跟踪
    -> 查看模拟成交状态
    -> 查看退出条件和模拟持仓状态
    -> 回到多日分析判断策略稳定性
```

不建议新增独立一级导航“策略分析”。原因是每日复盘已经拥有最重要的上下文：

- 哪一天产生了信号；
- 哪个批次运行了哪些策略；
- 哪些股票被哪些策略选中；
- 用户对股票做了观察或排除处理；
- D1/D3/D5/D10 跟踪结果；
- 多日策略汇总。

新增页面会把这些信息拆散，用户需要在“选股结果”“每日复盘”“历史回测”“交易系统”之间来回跳转，反而削弱分析闭环。

本方案推荐的产品结构是：

```text
每日复盘
├── 单日复盘
│   ├── 策略概览
│   ├── 全部股票
│   ├── 多策略共振
│   └── 信号详情 / 模拟跟踪详情
└── 多日策略分析
    ├── 策略概览
    ├── 全部股票
    ├── 多策略共振
    ├── 跟踪分布
    └── 模拟交易汇总
```

## 3. 用户和页面任务

### 3.1 主要用户

当前系统的用户是策略开发者和个人交易者。这个用户每天需要完成三类任务：

1. 判断今天的信号是否值得关注；
2. 检查过去一段时间策略是否稳定；
3. 查看信号是否进入模拟交易，以及模拟交易目前的盈亏和退出原因。

### 3.2 每日复盘的单一任务

每天打开页面后，用户最重要的问题是：

```text
今天哪些股票被选中？
为什么被选中？
信号当时的价格是什么？
如果按统一规则买入，现在表现怎样？
哪些持仓应该退出？
```

页面不能一开始用大量图表遮住这些答案。首屏应该先让用户看到批次状态、信号数量、跟踪完成度和股票表格。

### 3.3 多日分析的单一任务

多日分析要回答：

```text
在选定区间内，哪套策略的信号质量更好？
收益是否依赖少数极端样本？
D1、D3、D5、D10 哪个持有周期更合适？
按模拟成交价计算后，结论是否仍然成立？
```

所以多日分析的默认内容应该从当前的“成功率、收红率、平均收益”逐步扩展到收益分布、MFE、MAE、超额收益和模拟交易结果。

## 4. 页面结构调整

### 4.1 保留现有一级工作区

`App.tsx` 不新增一级 Tab。继续使用当前“选股 / 交易系统”等工作区结构。

每日复盘仍然位于现有选股相关工作区中，页面内部保留：

```text
单日复盘 | 多日策略分析
```

### 4.2 单日复盘调整

现有结构：

```text
左侧复盘批次 | 右侧每日策略复盘
```

建议调整为：

```text
┌───────────────────────────────────────────────────────────────┐
│ 单日复盘 | 多日策略分析                         数据更新时间    │
├──────────────┬────────────────────────────────────────────────┤
│ 复盘批次       │ 执行状态 / 跟踪状态 / 模拟盘状态                │
│                ├────────────────────────────────────────────────┤
│ 2026-09-24     │ 策略概览 | 全部股票 | 多策略共振                 │
│ 2026-09-23     ├────────────────────────────────────────────────┤
│ 2026-09-22     │ 股票表格                                         │
│ ...            │                                                  │
│                │ 展开行：信号 + 价格口径 + D0/D1/D3/D5/D10 + 模拟 │
└──────────────┴────────────────────────────────────────────────┘
```

左侧批次列表继续保留，因为它是每日复盘的重要时间轴。右侧增加状态信息，但不改变用户选择批次的方式。

### 4.3 多日分析调整

现有结构已经比较合理：左侧筛选，右侧结果。

建议扩展为：

```text
┌──────────────┬────────────────────────────────────────────────┐
│ 分析窗口       │ 分析事实摘要                                    │
│ 交易日范围     ├────────────────────────────────────────────────┤
│ 策略筛选       │ D1 | D3 | D5 | D10 跟踪卡                       │
│ 收益口径       ├────────────────────────────────────────────────┤
│ 成交模型       │ 策略概览 | 全部股票 | 共振 | 收益分布 | 模拟交易 │
│ 基准指数       ├────────────────────────────────────────────────┤
│ 应用分析       │ 表格 / 图表 / 分布 / 交易结果                     │
└──────────────┴────────────────────────────────────────────────┘
```

新增筛选项必须保持在左侧控制区，不要把大量筛选按钮塞进结果区顶部。

## 5. 首屏信息层级

### 5.1 单日复盘首屏

单日复盘右侧首屏建议按以下顺序：

1. 执行状态条；
2. 事实摘要；
3. 跟踪完成度；
4. 视图切换；
5. 股票或策略表格。

状态条增加：

```text
执行时间 | 策略执行状态 | 行情状态 | 跟踪截至 | 模拟盘状态
```

例如：

```text
2026-09-24 14:45:03 | 已完成 | 行情新鲜 | 跟踪至 2026-09-24 | PAPER · 运行中
```

### 5.2 事实摘要

保留现有事实摘要：

- 系统策略；
- 原始信号；
- 去重股票；
- 多策略共振；
- 候选范围；
- 已处理。

新增两个事实块：

- 有效信号价；
- 跟踪完成度。

建议显示：

```text
有效信号价     18 / 20
跟踪完成度      D1 92% · D3 78% · D5 61% · D10 44%
```

如果信号价缺失，不能把 `latest` 静默当成有效信号价。页面显示“缺少信号快照”，并允许用户展开查看原因。

### 5.3 多日分析事实摘要

保留当前：

- 分析天数；
- 纳入策略；
- 区间信号；
- 股票记录；
- 多策略共振；
- 平均评分。

新增：

- 当前收益口径；
- 当前模拟成交模型；
- D1/D3/D5/D10 有效样本数；
- 数据质量异常数。

推荐文案：

```text
收益口径       成交价后收盘
执行模型       次日开盘
有效样本       D1 328 / D3 291 / D5 260 / D10 198
数据质量       6 条待核验
```

## 6. 单日复盘视图设计

### 6.1 策略概览

现有策略概览表保留以下列：

```text
策略 | 状态 | 命中 | 错误股票 | 耗时 | 执行信息
```

建议新增：

```text
有效信号价 | 模拟计划 | 模拟成交 | D1收红率 | D5平均收益
```

第一版可以只增加：

- 信号快照率；
- 模拟计划数；
- 模拟成交数。

这样策略概览首先回答“今天策略有没有正常产生并进入执行链路”，而不是只看命中数量。

列建议：

| 列 | 说明 | 交互 |
| --- | --- | --- |
| 策略 | 策略名称 | 点击筛选当前策略 |
| 状态 | 执行成功、失败、进行中 | 点击查看错误 |
| 命中 | 原始信号数 | 点击进入股票视图 |
| 快照率 | 有效 `signal_price` 占比 | 异常时显示警告 |
| 模拟计划 | 已创建交易计划数 | 点击进入模拟交易视图 |
| 模拟成交 | 实际模拟成交数 | 显示成交率 |
| D1/D5 | 选定周期的简要收益 | 点击切换周期 |

### 6.2 全部股票

现有股票表已经包含信号日、代码、名称、共振、命中策略、评分、信号价、D1/D3/D5/D10 和状态。

建议调整列名和顺序：

```text
信号时间 | 代码 | 名称 | 共振 | 命中策略 | 分数
信号价 | 成交价 | D1 | D3 | D5 | D10 | 交易状态 | 操作
```

默认不展示所有字段，避免表格横向信息过载。推荐使用列设置按钮控制可选列：

- 默认列：代码、名称、策略数、分数、信号价、D1、D3、D5、D10、状态；
- 扩展列：行情时间、成交价、滑点、MFE、MAE、超额收益、计划股数；
- 调试列：数据源、计算版本、失败原因。

### 6.3 多策略共振

共振视图保留当前“同一股票被至少两个策略选中”的逻辑。

新增展示：

- 共振策略数量；
- 最高分和平均分；
- 信号时间是否一致；
- 是否生成一个合并模拟计划；
- 多策略信号与单策略信号的 D1/D5 对比。

注意：多个策略命中同一只股票时，界面要把“信号数”和“股票数”区分开。共振不代表系统会买入多次，模拟执行默认应合并为一笔股票订单。

## 7. 行展开与详情抽屉

### 7.1 为什么不直接跳新页面

当前每日复盘已经采用表格行展开显示信号和跟踪。继续使用行展开或右侧抽屉有三个好处：

- 不丢失当前日期和筛选上下文；
- 可以快速连续比较多只股票；
- 适合复盘时从表格逐条扫描。

建议：

- 行展开用于快速查看；
- 点击代码或“详情”打开右侧 `Drawer`；
- 行展开和抽屉使用同一份详情组件，避免两套字段逻辑。

### 7.3 详情区块

#### A. 信号事实

显示：

- 股票代码和名称；
- 信号日期；
- 信号时刻；
- `signal_price`；
- `quote_at`；
- `quote_source`；
- 行情延迟；
- 快照状态；
- 策略版本；
- 原始运行批次。

状态颜色：

- 有效：绿色或中性成功色；
- 过期：橙色；
- 缺失：红色；
- 推断的历史数据：灰色并带说明。

#### B. 信号解释

默认展示少量摘要：

```text
策略分 | 统一分 | 排名 | 命中策略 | 共振状态
```

点击“查看因子”后展开：

- 过滤条件；
- 加分因子；
- 各因子分值；
- 命中理由；
- 策略配置版本。

不要默认直接把完整 `detail_json` 放在页面上。JSON 只作为调试折叠区。

#### C. 模拟执行

显示不同执行模型的并列结果：

| 模型 | 状态 | 计划价 | 成交价 | 数量 | 滑点 | 失败原因 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 下一条报价 | 已成交 | 10.52 | 10.54 | 500 | +0.19% | -- |
| 次日开盘 | 已成交 | 10.61 | 10.61 | 500 | +0.85% | -- |

默认只选一个模型计算面板主收益，其他模型用于比较，不要混合聚合。

#### D. 跟踪结果

顶部提供口径切换：

```text
[信号价] [模拟成交价] [宽基超额]
```

下面显示 D0/D1/D3/D5/D10：

```text
周期 | 开盘收益 | 最高收益 | 最低收益 | 收盘收益 | MFE | MAE | 状态
```

完成周期显示实际数据；未完成周期显示：

```text
观察中 · 已获得 3/5 个交易日
```

缺失数据显示原因，不显示 0%。

#### E. 退出与持仓

当模拟执行已经成交时增加：

- 当前模拟持仓数量；
- 模拟成本；
- 当前模拟价格；
- 浮动收益；
- 最高价；
- 持有交易日；
- 当前止损线；
- 当前移动止盈线；
- 退出规则状态；
- 是否已生成待卖计划。

退出状态示例：

```text
持有中
已触发止损，待次日开盘
已触发移动止盈，待执行
已卖出
因涨停未买入
因停牌等待成交
```

## 8. 多日策略分析视图

### 8.1 分析窗口控制

保留当前左侧控制：

- 10 日；
- 20 日；
- 60 日；
- 自定义日期；
- 策略多选；
- 应用分析。

增加三组控制：

```text
收益口径：信号价 / 模拟成交价
执行模型：下一条报价 / 次日开盘
基准：无 / 沪深300 / 中证1000 / 行业指数
```

默认值建议：

```text
收益口径：模拟成交价
执行模型：次日开盘
基准：沪深300或项目默认宽基
```

原因是多日分析最终要服务于可执行交易，而不是只展示理论信号收益。但用户必须能切换到信号价，观察策略本身的预测能力。

### 8.2 策略概览表

当前策略概览已经有信号数、运行日、股票数、均分、共振和 D1/D3/D5/D10。

建议分成三组表头：

```text
基本覆盖：运行日 | 信号 | 股票数 | 均分 | 共振
信号跟踪：D1 | D3 | D5 | D10
执行结果：计划数 | 成交数 | 成交率 | 净收益 | 最大回撤
```

每个 D 周期单元格显示三行：

```text
收红率 58.4%
平均 +1.32%
有效 128
```

执行结果在数据尚未接入时显示 `--`，不要用研究收益代替交易收益。

### 8.3 四个周期卡

保留现有 D1/D3/D5/D10 卡片，并新增：

- 中位数收益；
- 平均 MFE；
- 平均 MAE；
- 超额收益；
- 完成率。

建议卡片结构：

```text
D5                         260 条有效跟踪
收红率 61.5%   达标率 38.1%
平均 +1.84%    中位 +0.72%
MFE +4.90%     MAE -2.30%
超额 +0.66%    完成率 86.7%
```

当样本数小于配置阈值，例如 30 条时，卡片显示“样本偏少”，不要使用强烈的成功/失败颜色。

### 8.4 全部股票和共振表

多日分析里的股票表沿用单日股票表，但增加区间筛选：

- 只看 D5 已完成；
- 只看 D5 收益为正；
- 只看触发止损；
- 只看模拟成交；
- 只看信号价和成交价差异超过阈值；
- 只看数据质量异常。

共振表增加对照标签：

```text
单策略信号
双策略共振
三策略以上共振
```

便于判断共振是否真的提高了交易质量，而不是只提高了命中数量。

## 9. 新增多日分析子视图

不建议一次加入太多 Tab。建议分两期增加。

### 9.1 第一阶段：跟踪分布

在现有“策略概览 / 全部股票 / 多策略共振”后新增“收益分布”。

内容：

- D1/D3/D5/D10 收益分布；
- 平均值、中位数和分位数；
- 正收益比例；
- MFE/MAE 分布；
- 信号价与成交价收益差异。

图表可以先使用简单的横向条形图、分位数带和表格，不必第一版就引入复杂图表库。

推荐布局：

```text
┌─────────────────────────────────────────────────────────────┐
```

### 9.2 第二阶段：模拟交易

- 模拟计划数；

视图顶部必须显示：

## 10. 价格口径交互

### 10.1 页面必须显式显示当前基准

所有收益数字旁边都显示简短口径：

```text
D5 +3.20% · 成交价后收盘
D5 +4.10% · 信号价后收盘
D5 +1.05% · 沪深300超额
```

不能只显示 `+3.20%`，让用户猜它是相对什么价格。

### 10.2 口径切换位置

在多日分析结果卡顶部放一个紧凑的 Segmented：

```text
[信号价] [模拟成交价] [超额收益]
```

在单条信号详情中同样放一个 Segmented，保证用户从汇总点进明细后口径不变。

切换口径时：

- 保留当前日期范围、策略和周期；
- 只刷新派生收益；
- 在加载中保持旧结果并显示刷新状态；
- API 请求携带 `basis` 和 `execution_policy`；
- URL 或页面状态可恢复，避免刷新后回到默认值。

### 10.3 异常口径提示

历史旧数据没有可信 `signal_price` 时，显示：

```text
历史推断价
```

点击后说明：

```text
该记录使用旧字段 latest 推断，无法确认行情时间，不建议与新信号直接混合比较。
```

## 11. 价格路径图

### 11.1 第一版推荐

优先在信号详情抽屉中增加轻量路径图，而不是首屏放大图表。

图表横轴：


图表内容：

- 收盘价或相对收益线；
- 买入基准线；
- 止损线；
- 移动止盈线；
- D1/D3/D5/D10 标记；
- 退出触发点；
- 缺失或停牌区间。

如果有分钟数据，D0 单独显示 14:45 到 15:00 的短路径；没有分钟数据时明确标记“D0 盘中路径不可用”。

### 11.2 图表交互

支持：

- 信号价 / 成交价切换；
- 收益率 / 价格切换；
- 鼠标悬停显示日期、OHLC 和收益；
- 点击退出点查看规则；
- 点击某个 D 周期定位对应观察点。

- 使用过多动画；
- 用大面积渐变背景；
- 用图表颜色代替文字状态。

## 12. 模拟交易状态设计

### 12.1 表格状态

建议统一使用以下状态文案：

| 内部状态 | 页面文案 | 颜色 |
| --- | --- | --- |
| `not_created` | 未生成计划 | 默认 |
| `planned` | 待执行 | processing |
| `filled` | 已成交 | success |
| `partial` | 部分成交 | warning |
| `rejected` | 风控拒绝 | error |
| `unavailable` | 行情不可用 | warning |
| `holding` | 模拟持有 | processing |
| `exit_triggered` | 已触发退出 | warning |
| `closed` | 已结束 | default |

### 12.2 退出状态

退出相关状态不要只显示“止损”两个字，要显示触发和执行的区别：

```text
未触发
已触发，待次日开盘
已提交卖出
部分成交
已卖出
卖出失败，等待重试
```

### 12.3 当前页面的操作边界

在策略分析和每日复盘页面中，第一阶段只允许：

- 查看模拟计划；
- 查看模拟订单；
- 查看退出条件；
- 手动刷新状态；
- 添加复盘备注；
- 进入交易系统查看账户汇总。

不要在每日复盘表格里直接放“真实买入”和“真实卖出”按钮。真实订单操作应该留给交易系统，并且还要受到账户模式和权限保护。

## 13. 筛选和查询设计

### 13.1 单日复盘筛选

现有搜索框保留，并增加紧凑筛选菜单：

```text
策略 | 共振 | 快照状态 | 跟踪状态 | 模拟状态 | 用户处理状态
```

常用快捷筛选：

- 只看有效信号价；
- 只看待跟踪；
- 只看 D1 已完成；
- 只看触发止损；
- 只看已模拟成交；
- 只看多策略共振；
- 只看未处理。

筛选条件应显示在工具栏中，并支持一键清除。

### 13.2 多日分析筛选

左侧筛选区分为四组：

```text
时间：交易日范围
策略：策略多选
收益：口径、周期、基准
执行：成交模型、模拟状态、数据质量
```

默认折叠执行筛选，避免第一次打开时左侧过高。

### 13.3 表格排序

允许按以下字段排序：

- 评分；
- 共振数量；
- D1/D3/D5/D10 收益；
- MFE；
- MAE；
- 超额收益；
- 模拟成交状态；
- 信号时间。

排序字段应在表头显示当前方向，不能只改变数据而没有视觉提示。

前端先使用旧字段工作，新增字段通过可选属性接入。这样可以分阶段发布后端和前端。

## 16. 视觉设计方向

### 16.1 核心风格

采用“量化研究工作台”方向：

- 浅色背景；
- 紧凑表格；
- 细边框分区；
- 低饱和状态色；
- 数字使用等宽字体；
- 信息优先于装饰；
- 页面区块不使用大面积营销卡片；
- 圆角保持现有 8px 或更小。

现有主题已经定义了较好的基础：

```text
主色：#0f5bd8
背景：#eef2f8
容器：#ffffff
边框：#d7e0ec
正文：#102033
成功：#16825d
警告：#b77713
错误：#c73f3f
```

新增组件应沿用这些 token，不要给策略分析单独创建一套紫色或渐变主题。

### 16.2 收益颜色

使用项目已有平台涨跌颜色配置。不要在组件中硬编码“红涨绿跌”或“绿涨红跌”。

颜色还需要配合符号或文字：

```text
+3.20% ↑
-1.45% ↓
待观察
数据缺失
```

避免仅凭颜色传达正负，保证灰度和色觉差异下仍然可读。

### 16.3 数字排版

价格、收益、样本数、比例和时间戳使用稳定宽度：

```css
font-family: ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
```

收益至少保留两位小数，样本数不加过度装饰。数字更新时不应导致表格列宽跳动。

### 16.4 页面签名元素

页面可以保留一个专属于策略分析的视觉签名：

```text
“信号到 D10”水平路径带
```

它出现在单条信号详情中，用一条紧凑的时间轴连接：

```text
信号 D0 -> D1 -> D3 -> D5 -> D10
```

每个节点显示收盘收益和跟踪状态。这个元素体现策略分析的时间性，且比装饰性大图更有实际价值。

## 17. 响应式设计

### 17.1 桌面端

保持当前两栏布局：

- 左侧批次或筛选区宽度约 272px；
- 右侧结果区域占据剩余空间；
- 股票表格允许横向滚动；
- 详情抽屉宽度约 520px；
- 图表最小高度 220px。

### 17.2 中等宽度

在 781px 到 1150px：

- D1/D3/D5/D10 卡片两列展示；
- 事实摘要三列展示；
- 过滤项保持单列；
- 表格仍然横向滚动；
- 详情抽屉缩小到 440px。

### 17.3 移动端

在 780px 以下：

- 左侧批次列表变为横向滚动条；
- 单日复盘和多日分析控制区变为单列；
- 事实摘要两列；
- 周期卡单列；
- 表格保留必要字段，详细字段移入抽屉；
- 股票表格不强行压缩所有列；
- 代码和名称固定，其他信息横向滚动；
- 抽屉占满屏幕宽度；
- 退出规则和信号事实按纵向区块排列。

移动端首屏只保证：

```text
股票 | 当前收益 | 状态 | 进入详情
```

不要为了塞下所有指标而使用过小字体。

## 18. 加载、空状态和错误状态

### 18.1 加载状态

页面分开处理：

- 批次加载；
- 当前批次加载；
- 多日分析加载；
- 单条信号详情加载；
- 路径图加载。

刷新分析时保留现有数据，按钮显示 loading，不要让整个页面闪成空白。

### 18.2 空状态

不同空状态使用不同说明：

```text
暂无系统策略日报
策略执行后在这里查看结果
当前区间没有策略信号
当前筛选没有股票
该信号还没有完成 D5 跟踪
当前没有模拟成交
```

空状态应告诉用户下一步动作，例如调整日期、清除策略筛选或等待跟踪完成。

### 18.3 错误状态

错误信息要区分：

- 策略运行失败；
- 行情同步失败；
- 跟踪数据缺失；
- 模拟执行失败；
- 详情接口失败。

错误区域提供重试按钮，并保留已有结果。不要把后端错误原文直接塞进整个页面；详细错误可折叠查看。

## 19. 交互细节

### 19.1 批次切换

切换批次时：

- 保留当前单日视图类型；
- 清空只针对当前批次不适用的选中行；
- 保留搜索词是否合理需要评估，建议保留；
- 自动更新页面标题和信号日期；
- 跟踪状态显示新的 `as_of`。

### 19.2 行展开

同一时间只允许一个或少量行展开，避免大量路径数据同时渲染。点击代码打开行情弹窗时，不要关闭展开状态。

### 19.3 详情抽屉

打开抽屉时：

- URL 可增加 `signal_id` 查询参数，便于刷新和分享；
- 关闭后回到原表格滚动位置；
- 切换上一条/下一条信号，保持当前筛选条件；
- 路径图和执行详情按需加载；
- 加载失败不影响信号基本信息显示。

### 19.4 导出

每日复盘和多日分析都支持导出，但导出文件必须带元信息：

```text
导出时间
日期范围
策略筛选
收益口径
成交模型
基准指数
计算版本
```

导出数据至少包含：

- 信号时间；
- 股票代码；
- 策略；
- 评分；
- 信号价；
- 成交价；
- D1/D3/D5/D10 OHLC 收益；
- MFE；
- MAE；
- 超额收益；
- 模拟成交状态；
- 数据质量。

## 20. 开发阶段拆分

### 阶段 1：调整现有每日复盘字段

目标：不改变整体布局，先让现有表格显示更可靠的信号信息。

改动：

- `latest` 改为优先显示 `signal_price`；
- 增加信号时间和行情时间；
- 增加快照状态；
- 在展开详情中显示信号价来源；
- D1/D3/D5/D10 显示明确的收益口径；
- 增加跟踪完成度。

验收：用户能判断每条信号的价格是否真实来自 14:45 左右的行情。

### 阶段 2：增加跟踪明细

目标：把现有跟踪从“一个收益数字”提升为完整的 D 周期指标。

改动：

- Dn 开盘、高、低、收收益；
- MFE；
- MAE；
- 最大路径回撤；
- 目标和止损触发；
- 数据质量和完成状态；
- 详情抽屉路径图。

验收：点开任意信号，可以追溯从 D0 到 D10 的路径和计算基准。

### 阶段 3：增加多日收益分布

目标：避免多日分析只看平均值和成功率。

改动：

- 增加“收益分布”子视图；
- 增加中位数和分位数；
- 增加 MFE/MAE 分布；
- 增加信号价/成交价切换；
- 增加宽基超额收益。

验收：用户可以判断收益是否被少数极端股票拉高。

### 阶段 4：增加模拟交易视图

目标：在每日复盘内查看策略信号进入模拟盘后的状态。

改动：

- 模拟计划数、成交数、拒绝数；
- 模拟持仓和已结束交易；
- 退出规则和卖出状态；
- 模拟账户净值；
- 按策略归因。

验收：从日报中的一条信号可以追踪到模拟订单、模拟持仓和退出结果。

### 阶段 5：与交易系统联动

目标：每日复盘负责信号和策略判断，交易系统负责账户、订单和真实执行。

改动：

- 在信号详情显示交易计划；
- 只提供“查看交易计划”入口；
- 交易系统显示待买、待卖和成交状态；
- 返回订单和持仓链接；
- 实盘操作不直接放在每日复盘表格中。

验收：用户能从信号进入交易系统查看执行状态，但不会误触真实下单。

- 缺少快照时显示明确状态；
- 模拟成交失败时显示失败原因；
- 模拟持仓退出事件可追踪；
- 筛选、排序和分页互不破坏；
- 导出包含筛选条件和计算版本。

### 21.2 数据一致性测试

- 表格中的 D5 收益与详情中的 D5 收益一致；
- 策略概览的样本数与股票视图聚合一致；
- 信号价口径和成交价口径切换后数值正确；
- 模拟成交数不超过有效交易计划数；
- 已平仓模拟交易不会显示为当前持仓；
- `signal_at`、`quote_at` 和 `created_at` 的语义不混用。

### 21.3 响应式测试

至少测试：

- 1440 x 900 桌面；
- 1280 x 800 笔记本；
- 900 x 1100 平板；
- 390 x 844 手机；
- 代码、名称、收益和状态没有重叠；
- 表格可横向滚动；
- 抽屉在移动端不超出屏幕；
- 过滤控件文字不会被截断到无法理解。

### 21.4 可访问性

- 图标按钮提供 `aria-label` 和 Tooltip；
- 状态不能只用颜色表示；
- 键盘可以切换 Tab、打开详情和关闭抽屉；
- Focus 状态清晰；
- `prefers-reduced-motion` 下不使用非必要动画；
- 表格列标题和数据有明确关联。

## 22. 推荐的第一版页面结果

第一版不要一次实现全部统计能力，建议最后落地成下面这个实际页面：

```text
每日复盘

[单日复盘] [多日策略分析]

单日复盘：
左侧：复盘批次
右侧：
  执行状态 + 行情状态 + 跟踪截至 + 模拟盘状态
  系统策略 / 原始信号 / 股票 / 共振 / 有效信号价 / 跟踪完成度
  [策略概览] [全部股票] [多策略共振]
  股票表：信号价、成交价、D1、D3、D5、D10、状态
  展开：信号事实、策略理由、模拟执行、价格路径、退出状态、备注

多日策略分析：
左侧：日期、策略、收益口径、成交模型、基准
右侧：
  区间事实摘要
  D1/D3/D5/D10 周期卡
  [策略概览] [全部股票] [多策略共振] [收益分布]

```

## 23. 结论

这套 UI 不应该把每日复盘和策略分析拆成两个产品。每日复盘本身已经是最自然的工作流入口：当天批次负责产生上下文，多日分析负责判断稳定性，行详情负责解释单条信号，模拟交易负责验证可执行性。

最终的页面职责应是：

```text
每日复盘 = 信号事实 + 跟踪结果 + 策略比较 + 模拟执行入口
交易系统 = 账户 + 订单 + 成交 + 持仓 + 实际收益
```

第一步先改造 `DailyReviewWorkspace`，把信号价格和 D1/D3/D5/D10 详情做好；第二步增加收益分布和模拟成交；第三步才和交易系统的订单、持仓、收益面板联动。这样用户始终在熟悉的每日复盘页面里完成判断，同时系统也能逐步演进成策略驱动的低频量化交易平台。
