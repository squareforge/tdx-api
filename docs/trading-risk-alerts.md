# 持仓交易价位与 Webhook 预警

在“交易系统 → 持仓与交易”新建买入记录，选择股票、买入日期并填写买入价，即会生成止损价与两档止盈价。填写股数后显示到止损价的预计亏损金额。估算不包含手续费及跳空滑点。

## 计算规则

- 使用买入日之前的完整、不复权日 K，避免买入后的数据和后续复权改变原始成交价格尺度。
- 由交易日历确认上一交易日；最新完整日 K 必须覆盖该日，且至少有 15 根有效日 K。缺失、过期、非法价格或未来买入日期均不生成建议价。
- ATR 使用 Wilder ATR(14)，最多取买入前 120 根日 K 初始化和递推。
- 支撑优先采用最近 20 根日 K 中已确认的波段低点：低点左右各两根日 K 均已在买入前完成。没有合适波段低点时，使用近 5 日低点。只采用低于买入价且距离不超过 3ATR 的低点。
- 初始止损为 `min(买入价 − 2ATR, 支撑 − 0.2ATR)`；无邻近支撑时只用 `买入价 − 2ATR`。止损向下取到分。
- `R = 买入价 − 止损价`，第一止盈为 `买入价 + 1.5R`，第二止盈为 `买入价 + 2.5R`，止盈向上取到分。
- 参考高点早于第一止盈价时，计算依据中提示上方阻力。

这些倍数是可解释的初始规则，尚未做策略样本外校准，不能视作最优参数。页面同时展示数据日期、ATR、风险幅度和计算依据。

手动价位优先；手动修改止损时，未手动修改的止盈会按新的 R 更新。保存后重新编辑会保留已保存价位。改变股票、买入价、买入日期或点击“重新计算并采用建议价”时重新计算；不会随行情自动下移已有止损。

## 启用推送

1. 在 Webhook 配置里启用渠道，事件订阅允许 `trade.alert`（或 `*`、空数组）。编辑渠道时可以点击“订阅持仓止盈止损预警”。
2. 在买入记录中开启“Webhook 预警”，选择渠道并保存。
3. 后台 selection-worker 在交易时段检查新行情。网页可以关闭，但行情服务与 selection-worker 必须持续运行。

最新价小于等于止损价触发止损，大于等于目标价触发对应档止盈。消息包含股票、买入价、触发价、最新价、剩余股数及行情时间。跳空同时越过两档时只发第二档，并将当天第一档记为已覆盖。

按“交易记录 ID + 预警类型 + 渠道 + 北京时间日期”持久化去重；每种类型每天最多成功提醒一次。改价、开关切换和进程重启不会清空当天记录，下个交易日重新计数。同一股票有多笔买入时，各笔交易保留自己的价位，卖出按先买先卖计算剩余股数；卖完的记录不提醒。

关闭某笔预警、删除该笔记录、清仓、关闭或删除所选渠道后停止发送。每次发送前会重新读取记录和渠道。

持仓行的“删除持仓”会直接删除项目账本中的这笔买入记录，无需先录入清仓卖出。已有部分卖出时，后台按先买先卖自动扣除归属本笔买入的卖出数量；完全归属本笔的卖出行一并删除，共享的卖出行保留其他买入的数量，计划亏损与实际盈亏金额按保留股数比例调整。其他买入记录的剩余持仓不变。卖出行的“删除记录”只删除该笔卖出，并重新计算剩余持仓。删除操作在数据库事务内完成，不产生模拟成交或券商订单；已发送通知的去重记录保留。

删除接口为 `DELETE /api/trading-system?id=<交易记录 ID>`，返回更新后的完整交易状态。

只处理交易时段内的有效新行情，拒绝来源标记过期或超过 3 分钟的行情。后台还会确认交易日。明确返回失败的发送最多尝试三次，间隔至少一分钟；网络超时等无法确认对方是否收到的情况不自动重发，避免重复通知。HTTP 已经发出的请求无法撤回。

数据库增加 `trade_alert_deliveries` 表。现有交易记录默认不开启新增预警，现有决策笔记的 `quote.alert` 是独立通知来源。

## 验证

- 前端：`npm run build`；计算规则：`node --experimental-strip-types --test tests/tradeRisk.test.ts`（在 apps/web/frontend 下）。
- Go：workbench-core、selection-worker、market-service 与 web 各自运行 `go test ./...`。
- Webhook 自动化验证使用本机测试接收器，不向真实渠道发送测试消息。
